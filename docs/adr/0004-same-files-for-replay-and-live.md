# 回放与盘中实时读同一批落盘文件；盘中回放定位为实盘验证而非历史验证

盘中模拟的两个事件源（回放 / 盘中实时）读同一批雷达落盘文件，而不是各接
一套数据。盘中实时读 `radar.json` 的当前快照时刻，回放读 `intraday_px_{date}.json`
的全量快照时刻序列 —— 两者是同一份数据的不同读取方式。

理由：这是「不同策略使用同一份数据源」这个诉求能成立的唯一方式。实测验证
同一策略在回放模式与盘中实时模式下产出完全一致的成交序列。

## Consequences

盘中粒度的历史数据只有 `intraday_px_{date}.json` 已有的分区（约 8 天），
**且票池有幸存者偏差** —— 雷达只记录涨幅 ≥1% 或概率 ≥0.2 的票，没涨起来
的票没记录。

因此定位必须分清：

- **盘中回放** = 实盘验证（验证策略在真实盘中数据上的行为是否正确），
  **不是**历史验证
- **日频回测**（`market.daily_panel` 2019-11 起，窗口充足）才能做历史验证
- 严格的历史因子验证继续用 `research/*.py` 的既有脚本

不要用盘中回放的结果去推断策略的长期期望收益 —— 8 天样本 + 幸存者偏差
不足以支撑任何统计结论。

## 结构层数据源

策略盘前需要的结构分不从雷达的 presignal 影子字段取（那个字段是信号触发
时才挂上的，盘前拿不到），而是由数据源从日线面板现算全市场结构分。这样
盘中与回放都能用，且确定性可复现。
