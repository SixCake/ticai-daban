# ticai-daban — A股题材打板研究与盘中监控平台

围绕「题材（热点）打板」这一 A 股特有交易场景，从 0 搭建的**数据底座 + 统计研究 + 盘中实时监控**一体化项目。

核心世界观（游资视角）：**热点按涨停家数计，每只涨停股独占归属一个概念**。项目以此为口径建立涨停事件库与题材日度快照，在此之上做无前视条件统计研究，并提供盘中实时的题材天梯、角色徽章、半路前向预警与题材/申万资金流雷达。

方法论铁律：**任何新维度必须经历史验证后方可集成**。每个研究编号（`research/NN_*.py`）先做 walk-forward 前向验证与牛/熊/震荡三段环境复核，通过后其阈值才被冻结进 `core/`；未通过的假设明确记为「证伪项」并禁用。

> 本项目为量化研究项目，所有代码与结论仅供学习交流，**不构成任何投资建议**。

## 项目能做什么

五层递进：

1. **数据层（collect/ + build/）**：tushare 涨停事件（2019-11 至今）+ 开盘啦题材事件（2024-01 至今）+ 同花顺涨停池榜单（2023-11 至今）+ 全 A 日线面板 + 题材成分快照 + 申万 2021 行业映射，加工出事件富化表（一字板判定、T+1 三口径收益）、题材日度快照（独占归属涨停家数、最高连板、龙头、题材年龄）与龙头因子日表（qscore/sscore）。
2. **研究层（research/ + docs/）**：在事件库与 20 秒雷达日志上做无前视条件统计——首板特征、封单额成交建模、归属口径 A/B、角色验证、概率校准、半路因子五轮迭代、龙头因子迁移、组合闸门、融合消融、情绪周期校准、跷跷板验证、高位短板状态机、竞价量比验证、因子区分度四关与分位化裁决，共 33 个研究编号。
3. **盘中监控（apps/poller + server + web/dashboard）**：每 60 秒拉取当日涨停池 → 实时独占归属算题材天梯 → 识别现实格候选 → 角色徽章，深色五页签 Web 看板（盘中实时 / 复盘梳理 / 预警雷达 / 申万资金 / 策略模拟+策略回测）。
4. **预警雷达（apps/radar）**：每 20 秒全量扫描 753 个题材概念约 4550 只成分股的实时行情，自算题材热度排名（附东财板块榜对照）、未板股涨停概率排名、**半路前向信号 S1/S2/S3**（封板前感知）、V5 结构层影子评分、龙头拐头跷跷板事件流、申万一级/二级资金聚合，并全量记录校准日志供收盘标注与概率校准研究。
5. **策略模拟层（rqalpha_mod_ticai/ + strategies/ + apps/sim）**：基于 rqalpha 的通用策略框架，四段生命周期钩子（盘前/竞价/盘中/收盘）、一策略一进程一账户相互隔离、AI 走 Feed 订阅不进策略代码、执行口径施加真实撮合约束（涨停不能买/无量撤单/T+1/成交概率抽样）。回放与盘中实时读同一批雷达落盘文件，故两者结果一致。看板「策略回测」页签运行/列表/查看回测详情；「策略模拟」页签管理模拟实例（可选某次已完成回测作为起点继承结束持仓+现金），同一套指标/曲线盘中实时产出。

## 快速开始

```bash
git clone https://github.com/SixCake/ticai-daban.git
cd ticai-daban
pip install -r requirements.txt

# 配置 tushare token（三选一：环境变量 / .env / ~/.zshrc）
cp .env.example .env   # 编辑填入 TUSHARE_TOKEN
```

首次建仓数据（全量约 10-20 分钟，均支持增量续跑，中断后重跑即可）：

```bash
python collect/fetch_kpl_concepts.py   # 开盘啦题材板块+成分快照（默认题材源）
python collect/fetch_concepts.py       # 同花顺概念列表+成分快照（回滚对照源）
python collect/fetch_kpl_events.py     # 开盘啦涨停/炸板事件（含题材标注, T+1）
python collect/fetch_limit_events.py   # 涨停事件全量（约6分钟）
python collect/fetch_ths_limit.py      # 同花顺涨停池榜单（涨停原因/板型/封板状态）
python collect/fetch_daily_panel.py    # 日线面板（纯tushare逐日拉取，最耗时）
python collect/fetch_sw.py             # 申万2021行业一级/二级成分映射
python build/enrich_events.py          # 事件×日线 → 一字板/T+1收益
python build/attribute.py              # 独占归属
python build/theme_daily.py            # 题材日度快照
python collect/factor_longtou.py       # 龙头因子日表（qscore/sscore/环境）
```

> 日线面板：如你已有前复权日线 parquet 数据（每文件一只股票，列含
> datetime/open/high/low/close/volume），可设环境变量 `LAB333_DAILY_DIR`
> 指向该目录以大幅加速历史段构建，tushare 只负责补尾；未设置则全部走
> tushare `pro.daily` 逐日全量（注意接口积分与频率限制）。

启动盘中监控平台（默认端口 8765）：

```bash
bash start.sh                # poller + 看板服务 + 预警雷达
bash stop.sh                 # 停止全部
bash daily_update.sh         # 收盘后增量更新事件库并重跑轨迹标注
```

打开 http://localhost:8765 即可看到四页签看板。闭市时 poller/雷达自动休眠（轮询间隔拉长），看板回退展示最近交易日快照。

### 可选：盘前自启（macOS）

竞价量只在 09:25:00~09:29:59 可采（该时段无连续竞价成交，tick 的当日累计量即竞价量；09:30 后混入盘中成交永久不可分离），所以雷达必须在 09:25 前就绪，并留足 QMT 推送订阅预热时间——推送未就绪时竞价时段会降级到日 bar 横截面，把上一交易日的收盘/涨幅/涨停价当成当日竞价行情。

```bash
bash deploy/launchd/install.sh              # 安装：工作日 09:10 触发 start.sh
bash deploy/launchd/install.sh status       # 查看安装状态
bash deploy/launchd/install.sh run-now      # 立即触发一次（start.sh 幂等，不会重复拉起）
bash deploy/launchd/install.sh uninstall    # 卸载
```

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `AUTOSTART_AT` | `09:10` | 盘前启动时刻 `HH:MM` |
| `AUTOSTART_LABEL` | `com.ticai-daban.morning` | launchd 任务名，改名可并存多份安装 |

优先级为 命令行 `--at`/`--label` > shell 环境变量 > `.env` > 默认值（与 `config.py` 的 `setdefault` 语义一致）。项目路径由脚本自身位置推导，无硬编码；模板在 `deploy/launchd/*.plist.template`，渲染后写入 `~/Library/LaunchAgents/`，运行日志落 `logs/launchd.log`。非交易日由拉起的进程自行休眠（`core/calendar.py` 判定），无需额外排除节假日。Linux 用户可参照该模板改写 systemd timer。

### 可选：两个口径开关

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `CONCEPT_SOURCE` | `kpl` | 题材分类源：`kpl`=开盘啦题材（研究25 A/B 胜出）/ `ths`=同花顺概念（旧源，保留供回滚对照） |
| `QUOTE_SOURCE` | `tx` | 实时行情源：`tx`=腾讯 http / `qmt`=大 QMT FormulaServer 快路径 |

`QUOTE_SOURCE=qmt` 需额外配置 `BIGQMT_*` 系列环境变量（账号、Redis 主机/端口/库、FormulaServer 主机），并盘前预建缓存：

```bash
python -m quotes.qmt build-cache      # 全市场名称 + 近5日每分钟均量缓存
```

QMT 链路的实时行情走 Redis pubsub 增量累积，推送陈旧或盘前/收盘时自动降级到 FormulaServer 日 bar 横截面；配置全部来自环境变量，切换局域网/云隧道只改两个 HOST，代码零改动。

## 分层架构

依赖方向单向：apps → core/quotes → 无。core 是领域逻辑唯一出处（纯计算，无网络、无快照写入）；quotes 只做网络请求与源格式归一化；apps 只做进程编排。同一口径（归属/角色/热度/概率/现实格/前向信号/结构评分）全项目只有一份实现，盘中与离线共用。

## 数据源与口径

| 数据 | 接口 | 覆盖 | 说明 |
|---|---|---|---|
| 涨停事件 | tushare `limit_list_d(limit_type='U')` | 2019-11-28 → 今 | 主源。连板数/封单额/首封/末封/炸板次数/行业/市值/换手 |
| 开盘啦事件 | tushare `kpl_list` | 2024-01 → 今 | 涨停+炸板事件，**theme 字段是题材归属层的权威数据源**（T+1） |
| 涨停原因 | tushare `limit_list_ths` | 2023-11 → 今 | lu_desc 涨停原因/tag 板型/status 封板状态；当日 16 点后可拉，北交所标的缺失由开盘啦兜底 |
| 涨停价 | tushare `stk_limit` | ≥2019 | up_limit/down_limit，判一字板用 |
| 题材板块 | tushare `kpl_concept` / `kpl_concept_cons` | 当前快照 | 开盘啦题材（默认源，雷达宇宙约 753 概念/4550 成分股）；成分接口单页上限 3000 行须 offset 翻页 |
| 同花顺概念 | tushare `ths_index(exchange='A', type='N')` + `ths_member` | 约395个快照 | 回滚对照源。过滤指数样本类/属性类噪音后约350个真题材 |
| 申万行业 | tushare `index_classify` + 逐 L2 `index_member` | 当前快照 | SW2021 一级/二级成分，覆盖约92%，供雷达分级资金聚合 |
| 当日涨停池 | akshare `stock_zt_pool_em` | 近期日期 | 盘中轮询主源。注意：未开盘日请求会返回上一交易日数据，须自行定标 |
| 实时行情 | 腾讯 `qt.gtimg.cn`（60只/批, GBK） | 盘中 | f[3]现价 f[4]昨收 f[32]涨幅% f[37]额(万) f[38]换手 f[47]涨停价 f[49]量比 |
| 实时行情（快） | 大 QMT FormulaServer + Redis pubsub | 盘中 | 同契约适配层，推送增量累积，陈旧自动降级日 bar 横截面 |
| 东财板块榜 | `push2.eastmoney.com` | 盘中 | 热度外部对照（f3涨幅/f22涨速/f104涨家数/f128领涨），失败自动切 push2delay 备源 |
| 日线面板 | tushare `pro.daily`（可外挂本地前复权目录） | 2019-11 → 今 | 收益一律用 pre_close 官方除权口径 |

**已知局限（解读结论时必须记住）：**

1. 题材成分（`kpl_concept_cons` / `ths_member`）都是当前时点快照，无 in_date/out_date → 回溯历史存在幸存者偏差（新概念成分股被错误归入历史、退市股缺失）。项目接受该局限，结论解读时注意。
2. 涨停事件起点 2019-11-28（约 6.8 年）；开盘啦题材标注起点 2024-01（约 2.7 年）；同花顺涨停原因起点 2023-11。跨源研究须注意窗口不齐。
3. 超大杂烩概念（如融资融券 3858 只成分）与属性类概念（预增/重组/股权激励等）必须过滤，否则污染独占归属——过滤规则见 `config.py`（成分数上限 1500 + 名称关键词黑名单）。
4. 开盘啦 `kpl_list` 为 T+1 数据，当日盘后次日才可拉；同花顺榜单当日 16 点左右更新。`daily_update.sh` 的顺序已按此约束固定（日线面板补尾必须先于事件富化）。

**打板收益口径**：T 日涨停价(=收盘)买 → T+1 开盘卖，`ret = next_open_ret = t1_open/t1_preclose - 1`。可行性过滤：剔除 T 日一字板（排板无法成交）与 ST；T+1 一字/开盘跌停作为卖出端风险单独报告。

## 核心方法

### 独占归属算法（iterative greedy）

1. 过滤：剔除 `is_theme=False` 的概念（指数样本类/属性类/超大杂烩）。
2. 初始化：每只涨停股的候选 = 其成分概念 ∩ 当日有涨停股出现的概念。
3. 迭代：统计每概念当前归属家数 cnt → 每股归到候选中 cnt 最大者（平票取当日涨停密度 raw/成分数 更高者——真热点优先；再平取成分数更小者；再平取代码升序）→ 重复至不动点（通常 <5 轮）。
4. 无候选概念者归入「未分组」（保留行业字段）。

密度 tie-break 的由来（研究03）：早期「成分数小优先」会把龙头锁进小杂概念（深中华A→两轮车而非黄金概念、金健米业→乳业而非粮食概念），大热点漏标 48.8%；改密度优先后漏标降至 21.7%，现实格样本 n 984→4237，逐年全正。

### 题材分类源 A/B（研究25，定稿 kpl）

开盘啦题材的事件级标注（`kpl_list.theme`，顿号分隔多题材、第一个为主归属）对比同花顺概念投票归属：**未归属率 0.15% vs 1.25%，最大簇占比 23% vs 48%**（同花顺易把大量涨停堆进单一巨簇）。故 `CONCEPT_SOURCE` 默认切 `kpl`，同花顺源保留供回滚对照。盘中延续法候选、触及层与动态成分取近 `KPL_THEME_WINDOW=60` 个交易日（约一个炒作周期）内被开盘啦标注过的（股票, 题材）对。

### 题材热度 v2（雷达自算口径，尺寸中性）

```
heat = headx + 30×dens5 + 50×dens7 + 1.5×头部20只3分钟涨速
       + 0.6×放量均量比(≥3%成员) + 90×zdens
```

- `headx` = top10 均涨 − 同尺寸抽样基线（全市场涨幅降序中 rank N/(n+1)..10N/(n+1) 段均值，N=全市场、n=题材成分数，次序统计量期望），衡量「头部超额」；
- `dens5/dens7/zdens` = 涨>5% / >7% / 涨停家数占成分数比例。

由 v0（top10 + 0.5×n5 + 0.8×n7 + …）升级而来：v0 的原始家数项随成分数线性放大，600-1400 成分的大筐（国企改革 1380 / 新能源汽车 978，dens5 仅 3-6%）霸榜，真同动小簇（粮食/CRO 25-93 成分，dens5 13-20%）被埋；v2 用密度 + 头部超额消除尺寸偏差。实测新能源汽车由榜 1 降至第 86 名，转基因/粮食/化债等密集簇居首；与东财板块榜的匹配子集 Spearman ≈ 0.67。热点阈值 heat≥12（≈全市场 p95）。剔除 ST/北交所/无涨停价新股。

同一口径按申万 2021 一级/二级复用（`sw_aggregate`），产出「申万资金」页签的分级资金聚合与气泡图。

### 涨停概率 v0（启发式，校准中）

仅对未板股排名（已板不可买）：

```
z = -6 + 0.55×涨幅 + 0.5×min(涨速3m,3) + 0.35×min(量比,5)
      + 0.08×min(题材heat,15) - 0.30×距涨停%
prob = sigmoid(z)；临近涨停(价格≥涨停价×0.995)时 z = max(z, 4.0)
```

### 半路前向预警 S1/S2/S3（core/early_signal.py）

把「封板后才确认」提前到「拉升途中感知」。只用决策时刻之前的 20 秒轨迹，无未来信息；规则来自研究12（238 交易日全窗口）+ 研究14c（walk-forward 前向验证通过）+ 研究30（实盘复核修正）：

| 级别 | 判据 | 验证结果 |
|---|---|---|
| S1 提前感知 | 首触 ≥+1% | 观察名单，宁滥勿缺 |
| S2 确认 | 触 ≥+2% 且（颠簸高 `pathvol>PV_HIGH` / 颠簸中+急加速 `accel>4`） | 前向 1.95x，EV +3.65% |
| S3 高开确认 | 开盘后第 4 分钟判定：`gap≥5.2` 且开盘 3min 回撤 `odip≤0.05`；或 `gap≤5.2` 且 `amp3>4.3`；或开盘量爆 `vr_pct≥0.95` | 前向 89% 封板；叠加昨日收强 `y_cpos>0.6` 时 92% 封板、EV +4.47% |

三处已按证据修正的口径：

- **暴拉分支已移除**（研究15 证伪）：封板率 53% 但入场→次日仅 +0.2%，属追高吃溢价。
- **量爆分支改横截面分位**（研究30）：原绝对阈值 `vr≥5` 在生产口径下失效（开盘 20min 内中位数 7.4、`vr≥5` 占 73%），导致该分支占全部 S3 的 98% 且封板率 3.7% 低于宇宙基线 6.9%（反向）；改用同快照横截面分位后，样本外最优档（0.68~1.00）封板率 13.2% vs 最低档 4.9%。
- **该分支已从"竞价量爆"改名为"开盘量爆"**：它在 09:34 取样，用的是盘中量比而非竞价量比，原名一直在误导。真正的竞价量比另走影子字段（见下节）。

### 竞价快照与竞价质量闸（apps/radar._auc_capture，研究31）

竞价数据与盘中数据必须分开取。竞价量**只在 09:25~09:30 可采**——该时段无连续竞价成交，tick 的当日累计量就等于竞价量；09:30 后混入盘中成交永久不可分离。雷达在该窗口每轮重试，覆盖率达标即冻结，末轮强制冻结；竞价成交价则全天可从 `quote.open` 补。采不到竞价量的票 `vr/vrp/gate` 显式置 null，看板标"竞价量缺失"，绝不用盘中量比冒充。

产物 `data/live/auction_YYYYMMDD.json`；信号上挂影子字段 `auc={gap,vr,vrp,gate}`（照 V5 `struct` 做法，只展示不拦截触发，S1 门槛仍 ≥1% 不变）。闸只看板展示层生效：S1 观察名单默认只渲染过闸者。

口径：竞价量比 = 竞价量 ÷ 近5日每分钟均量（`emin=1`），与 tushare `stk_auction.volume_ratio` 同式（实测反推验证一致）；分位排名域 = 竞价涨幅≥1%（S1 候选域），阈值 `vrp≥0.90`。腾讯 `f[36]` 成交量量纲分板块（主板/创业板返手、科创板返股），已归一为股。T+1 由 `collect/fetch_auction.py` 补 `official` 子键作对照，**盘中值冻结不覆盖**（否则就是用未来信息验证当时的决策）。

研究31 验证结论（1.6 年窗口，63.5 万样本，三段市况）：

| 方案 | 过闸 n | 封板率% | 次日开胜率% | 次日收盘% |
|---|---|---|---|---|
| 未过闸（分位<0.90） | 571109 | 1.00 | **39.46** | 0.17 |
| A 分位≥0.90（现设计） | 63693 | 12.41 | 37.92 | 0.32 |
| B 分位≥0.95 | 31949 | 19.11 | 38.72 | 0.48 |
| C 绝对 vr≥2 | 55278 | 14.32 | 37.74 | 0.36 |
| D 涨幅≥2%×分位≥0.90 | 49883 | 14.66 | 38.75 | 0.39 |

**封板率维度是强因子**：5 档分位严格单调（档1 0.36% → 档5 7.69%，spread +7.33pp），四个方案在牛/熊/震荡三段全部同向（3/3），过闸组封板率是未过闸组的 10 倍以上。

**但次日收益维度是弱因子且胜率反向**：档5 的次日开盘胜率 37.73% 反而低于档1 的 41.27%，未过闸组胜率（39.46%）高于所有过闸方案。这再次印证「打板 EV 由入场价位而非封板率决定」——竞价爆量的票更容易涨停，但涨停后次日溢价并没有变好。

因此竞价闸**只作为观察名单的密度过滤器，不得用作买入信号**。

执行口径（研究17/18 验证：回踩无逆向选择，挂单等回踩 EV 单调升）：S2 挂限价单低于触发价 0.3~0.6 点等回踩；S3 挂限价单低于开盘价 0.5~1.0 点等回踩。每票每日每级只报一次。

### 龙头因子 qscore/sscore（core/longtou.py，研究22/23 冻结）

```
qscore 次日质量分(0-4) = (ldlr_prev<0.5) + (ind_rank>3.5) + (zb_cnt20≤1.5)
                        + (0.55<y_volr5≤2.2)
sscore 封板概率分(0-5) = (zb_cnt20≥0.5) + (ind_ztdens≥0.03) + (ind_rank≤3.5)
                        + (y_volr5<2.5) + (ind_breadth≥0.65)
```

逐档校准概率（test 段，冻结不改）：qscore 1→4 对应次日胜率 73%/81%/79%/86%，同档盈亏比 1.91/1.92/2.26/2.47；sscore 0→5 对应封板率 28%/23%/32%/41%/50%/60%。注意次日胜率随 sscore **降**（0.84→0.67）——聚焦度换次日弹性：高封档宜吃日内溢价，高质量档才适合隔夜。

任一成分缺失返回 None（不伪装为低分）。证伪项（禁用）：行业排名前 3 作次日质量加分（龙头稀缺性在打板场景方向相反）、`ld_prev` 绝对家数、`cycle_prev`/`adv_prev` 单独作闸门。

#### 适用人群纪律（研究32 四关复核）

两个分的阈值只在**打板语境**里有区分度，换人群即失效：

| 因子 | 人群 | 顶档占比 | 顶/底 lift | 档间 ρ | 判定 |
|---|---|---|---|---|---|
| qscore | 全市场 | 82.7% | 无标签 | 无标签 | ❌ 塌缩 |
| qscore | 主力规则池 test | 36.5% | 3.70x | +0.90 | ✅ 过闸 |
| sscore | 全 test 段（校准表原口径） | 1.1% | 1.71x | +0.83 | ✅ 过闸 |
| sscore | 主力规则池 test | 3.1% | 1.35x | +0.77 | ❌ G4 |
| sscore | 触板池（实盘标注） | 1.3% | 0.70x | −0.89 | ❌ G3/G4 |

同一套 qscore 阈值，全市场顶档占比 82.7%（塌缩），主力规则池 36.5%、5 档均衡、lift 3.70x —— **阈值一个字没改，只是人群变宽**。成分审计同理：`ldlr_prev<0.5` 在全市场命中 100%（恒真），在主力规则池仅 79.2%（标记关闸日，有区分度）；剔除它反而使 lift 由 3.70x 降到 1.99x。故**成分审计必须按目标人群做，「全市场恒真」≠「可剔除」**。

因此看板的因子分解由 `inDabanPool()` 限定在涨停/触板/半路信号池内，池外票显示口径守卫而非静默给分；徽章只展示档位、不展示校准概率小数（`qw`/`sp` 的验证人群是主力规则池日均 25 只，贴到全市场属口径越界）。

#### 区分度四关（`research/32_discrimination_gate.py`）

新因子入池前必过，且必须在**目标人群**上过闸（在其他人群过闸不作数）：

- **G1** 顶档占比 < 40%（>70% 判塌缩）
- **G2** 档数 ≥ 4 且最大档占比 < 50%
- **G3** 顶/底 lift > 1.3x
- **G4** 档间 Spearman |ρ| > 0.8 且方向与假设一致

任一不过 → 该因子在该人群下不可用，换人群或换因子，不要改阈值硬凑。

附：把二值累加改当日横截面分位可彻底消除塌缩（每档恒定 20%），但实测只对封板率有效（lift 1.75x、ρ=+1.00），对次日胜率反向（lift 0.90x、ρ=−0.90）—— 这批昨日静态因子本质是封板率因子，不是次日质量因子。

#### 分位化已评估并**不采纳**（研究33）

四候选并行回测（A0 二值累加 / P1 分位等权 / P2 分位减法 / P3 分位IC加权），目标锁定封板率，test 段 + 三段市况 + walk-forward：

| 方案 | test 顶-底 spread | lift | ρ | 偏多/震荡/偏空 | train→test 衰减 |
|---|---|---|---|---|---|
| **A0 二值累加** | **+32.0pp** | **2.14x** | +0.94 | +25.9/+31.8/+49.5pp | −4.9pp |
| P1 分位等权 | +12.3pp | 1.49x | +1.00 | +14.3/+10.4/+12.9pp | −0.1pp |
| P2 分位减法 | +12.5pp | 1.50x | +1.00 | +10.6/+12.2/+14.3pp | +2.2pp |
| P3 分位IC加权 | +14.9pp | 1.63x | +1.00 | +16.0/+14.0/+15.2pp | +1.9pp |

**裁决：保留冻结的二值累加，不引入分位化。**分位化用「分布均匀」换掉了「信号强度」—— 它虽完美单调（ρ=+1.00），但 spread 只有二值累加的 38%。而塌缩问题已由「限定人群」解决：在目标人群内 sscore 顶档占比仅 1.1%，四关全过，根本不存在塌缩。

次日胜率维度四个候选均反向（ρ = −0.14 / −0.70 / −0.60 / −0.90），分位化救不回来 —— 确认这批因子只能做封板率排序，不得用于次日质量/仓位分层。

### V5 两层架构（结构闸 + 融合排序，研究24/24b 定稿）

```
g_chip  = mean(ind_rank>3.5, zb_cnt20≤1.5, y_volr5∈(0.55,2.2],
               neg_streak≥2.5)                            # 结构闸 ≥0.6 合格
g_eco   = mean(pct(ind_ztdens), 1-pct(ind_rank), pct(ind_breadth),
               pct(zb_cnt20), vol甜蜜区)                 # 生态分
g_intra = mean(pct(r3), pct(pathvol))                   # 盘中分
V5      = 0.5×g_intra + 0.25×g_eco + 0.25×g_chip        # 融合排序
```

二元组任一成分缺失则弃用该项并按可用项重归一（不伪装为通过）。`ldlr_prev`（昨日涨停池/跌停池家数比）是全市场常量、无截面区分度（研究中它是跳时间的坏日闸门），故**不进 g_chip**，仅随输出透传供调用方另行环境降权。

分位网格 `pct()` 固化在 `data/meta/struct_grids.json`（train 段 200 分位降采样），盘中/实时**不得重新拟合**。落地三句话：① 扫板队列前置 `g_chip≥0.6` 结构闸；② 触发仍用盘中规则；③ 同分钟多触发按 V5 融合分降序分仓（MAX_POSITIONS=3），早盘信号优先。

当前在生产中为**影子输出**（不改触发逻辑），用于持续对照实盘表现后再切换。

### 情绪周期与分歧驱动仓位（core/cycle.py，研究27/28）

春夏秋冬四阶段（低位试错 / 主升 / 高位震荡 / 主跌）经研究27 验证对 T+1 **无稳定梯度**，故阶段降级为展示参照；真正有梯度的是分歧/一致维度（研究28，三环境方向一致 2/3 段通过验收）：

- `br` 炸板率 = 分歧释放强度；`yizi` 一字率 + `accel` 缩量加速率 = 一致强度；
- 仓位跟随分歧：高分歧 0.8 / 中性 0.5 / 高一致加速 0.2；
- 铁律还原：高位（6板+）做龙头、低位（首板一进二）试错、中位（3-5板）风险最大——高度分布条把中位单独标橙警示；
- 题材 mode：波龄 1=爆发（切换窗口）/ 2-3=主升 / ≥4=鱼尾（补涨性质，不能格局）。

与 V5 结构层同原则：**仅页面展示，不接入任何买卖拦截**。

### 高位龙头短板 5 态（core/shortboard.py，研究29）

近 N 日题材龙头 ∪ 市场高板即使今日未涨停也保留追踪，用 5 态刻画其高位状态。**仅作展示/风险标注，不含任何买入语义**——研究29 证伪了整个 cohort（6.5 年全历史，牛/熊/震荡三段一致，前向收益全负）：

| 状态 | T+1 开盘收益 | 风险排序 |
|---|---|---|
| 绕异动（缩量窄幅） | −0.4% | 最抗跌 |
| 断板观察 | −0.9% | |
| 逻辑失效 | −1.2% | |
| 二波候选 | −1.5% | |
| 放量分歧 | −1.7% | 最危险 |

关键反直觉结论：「放量换手分歧后冲高（二波候选）」历史平均是**追高/出货陷阱**而非机会；「缩量窄幅绕异动」才是最抗跌的高位状态。故 5 态按风险标注，冲高态标警惕而非看多。

### 龙头拐头 → 跷跷板（core/seesaw.py）

盘中监测龙头下跌时中军/后排跟跌、或存量资金切向另一板块的现象。龙头双口径（A=上一交易日 `theme_day.leader_code` 跨日延续，B=当日成分内涨幅最高者），下跌候选 D1 涨速转负 / D2 高点回落 / D3 破开盘线 / D4 放量下跌并行打点，事件后回填 +5/+10/+20 分钟的概念均跌、下跌家数占比与跷跷板对手概念热度变化，事件流落盘 `data/live/seesaw_YYYYMMDD.jsonl`。

## 研究结论摘要

编号与 `research/` 脚本、`docs/` 文档一一对应。

**研究01/02 — 首板统计与封单成交建模**：建立无前视条件统计框架；现实格候选口径＝题材独占涨停≥8家 且 炸板≥1次后回封 且 炸板≤3次 且 最后封板≤11:00，v2 归属下历史均值 +3.64%/笔（n=4237，日聚类 t=36.0）。

**研究03 — 归属 tie-break A/B**：密度优先 vs 成分数优先，见上文。

**研究04/04b — 角色体系验证**（T+1 开盘卖口径）：

- 龙头 +1.95%（t=59）；大热点(≥8家)内龙头 +3.87% vs 跟风 +2.52%；
- 连板延续（非龙头连板≥2）全角色最强 +2.74%/笔；
- 共振首板（wave 首日首板）+1.91%；
- 补涨（wave age≥2 首次出现、连板≤2）+2.07%，不随 wave 年龄衰减；
- 中军（成分内涨幅≥5%未涨停的成交额最大者）出现率 88-98% 无区分度、自身 T+1 -0.9~-1.0% → 降级为看板描述标签，不作买入信号。
- 龙头溢价逐年衰减（2019 +2.5% → 2026 +1.48%）但仍为正。

**研究05 — 涨停概率校准复盘**（1533 stock-day / 65 涨停）：v0 排名 AUC 0.92-0.95、召回 100% 成立；但校准失真——10cm 板 ≥90% 概率桶实际兑现 89.7%（诚实），20cm 板 ≥90% 桶仅 19%（严重过自信），中段 30-90% 二元化（实际全 0）。单变量分析：dist/pct/vr 正向，**换手率 tover 与题材热度排名 trank 是 v0 遗漏的强反向因子**（低换手、主线题材更易封板）。详见 `docs/research_05_涨停概率校准复盘.md`。

**研究06~18 — 半路因子五轮迭代**：从「涨停/触板分钟路径因子」出发，经假设驱动挖掘（07）→ 多日 OOS（08）→ 多维交互（09）→ 启动初期 +1% 信号（10）→ 触 +2% 决策时刻 OOS（11）→ 238 交易日全窗口扩展（12）→ walk-forward 前向验证（13/13b）→ 双队列修复高开盲区（14/14b/14c）→ 因子深挖二至五轮（15 VWAP位置/相对强度/情绪环境；16 复合叠加；17 板性习惯族/入场时机；18 遗留问题闭环），最终固化为 `core/early_signal.py` 的 S1/S2/S3。过程日志见 `docs/research_06_半路因子迭代日志.md`。

**研究19/20/21 — 面板、闸门与分钟级回测**：前几日因子逐日复盘面板 + 全规则胜率补全；指数/情绪环境闸门（坏日识别）；分钟级回测打通「信号→执行→持仓→出场」全链模拟。

**研究22/23 — 龙头二波思想因子迁移**：把龙头二波策略的因子迁移到打板场景做前向验证，产出 qscore/sscore 复合评分与组合闸门（应用前后对比回测）。借鉴来源见 `docs/research_07_龙头二波策略借鉴.md`。

**研究24/24b — 因子融合与消融（定稿）**：并行回测 V0 随机基线 / V1 仅盘中 / V3 三组加权 / V4 结构过滤+盘中排序 / V5 结构过滤+融合排序 / V6 结构过滤+纯结构排序。test 段组合级（每日 top3、30% 成交）对比：

| 指标 | V1(现有) | V5(最终) | 变化 |
|---|---|---|---|
| 买入点胜率 | 42.3% | 39.5% | −2.8pp（封板率 44.0%→41.2% 轻微代价） |
| 次日胜率 | 69.7% | **74.6%** | +4.9pp |
| 盈亏比 | 2.00 | **2.28** | +14% |
| Sharpe | 7.75 | **9.24** | +19% |

train/test 双段方向一致，月度跑赢 V1 3/4 月，三段行情无失效。V6（纯结构排序）次日胜率 85.5%/Sharpe 11.11 最高但封板率降至 30.7%——牺牲抓板概率换次日质量，不符合「先抓板」目标，仅适合低吸/半路队列参考。注：Sharpe/年化绝对值仍受样本选择偏差影响虚高，只采信组间相对值。

**研究25 — 双 A/B**：概念数据源 A/B（东财板块 vs 同花顺，后被开盘啦源替代）；龙头拐头→板块跟跌+跷跷板事件统计（下跌定义选优）。

**研究26/27/28 — 情绪周期校准**：四阶段 v0 校准 → 历史日频验证发现四阶段对 T+1 无稳定梯度但「冬」（高炸板=分歧释放）胜率反而高 → 引入分歧维度重构仓位（买在分歧卖在一致），三环境验收方向一致 2/3 段。

**研究29 — 高位龙头短板 + 二波状态机**：5 态精简状态机历史验证，全 cohort 前向收益为负，定位为展示/风险标注层（见上文）。

**研究30 — S2/S3 实盘复核与封板因子发现**：详见 `docs/research_08_s2s3实盘复核与封板因子发现.md`。三项产出：

1. **数据体检发现 `sealed_t` 字段与实际封板严重不一致**（`radar.py` 的 `setdefault` 遇 None 永不回填）→ 封板标签必须用 events 重算，已修状态推进逻辑；
2. **S3 竞价量爆口径失效诊断** → 改横截面分位（见上文）；
3. **封板因子 walk-forward 发现**：训练 65133 行 / 样本外 92037 行，全因子→收盘封板样本外 AUC 0.8333，剔除 dist/near 后的可交易因子集 AUC 0.8536（lift@1% 8.67x）。盈亏平衡测算：封板票 EV≈6.25%、未封板票 EV≈−0.55% → 需封板率 > 8.1% 才能打平（宇宙基线 6.9%），佐证「打板 EV 由入场价位而非封板率决定」——6% 以上入场数学上不可行。

**背景先验**（本项目立项依据）：次日追高侧（T+1 开盘买前日涨停股）结构性负 alpha；打板侧（T 日封板买→T+1 开卖）毛 +1.9~3.1%/年但逐年衰减——本项目的命题是验证「题材维度」能否在打板侧筛出正期望子集。两层打板体系的完整论述见 `docs/聚宽文章_两层打板体系.md`。

## 监控平台五页签

- **盘中实时**：poller 每 60 秒拉 akshare 涨停池 → 实时独占归属算题材天梯 → 现实格候选高亮。情绪条（涨停/炸板出池/断板率/最高连板）、题材天梯、连板天梯、涨停池全明细、当日炸板出池记录。炸板状态机用涨停池快照 diff 实现（上次在池本次出池=炸板出池；再入池=回封），逐笔写入 `data/live/intraday_YYYYMMDD.jsonl`。
- **复盘梳理**：选日期（支持默认最新、前后交易日跳转、一键最新）→ 当日现实格命中及其 T+1 兑现、前一交易日信号的兑现验证、题材/连板天梯、高位短板 5 态区、全池明细、历史统计；缺失日期现场构建并缓存。涨停原因悬停浮窗（同花顺 `limit_list_ths` 为权威源 + 开盘啦兜底）附日 K 线图。
- **预警雷达**：每 20s 全扫成分股 → 题材热度自算排名（东财对照列）+ 未板股涨停概率榜 + S1/S2/S3 前向信号 + V5 结构层影子分 + 跷跷板事件流。概览卡（热点题材/冲板候选/高概率/触板数）、榜内排名自适应底色、概率进度条、新晋上榜与概率变化标记、距板≤1.5% 闪烁提醒、题材行展开领涨成分、信号表三价展示与个股分时详情弹窗。
- **申万资金**：SW2021 一级/二级分级资金聚合气泡图，支持 top5 对比、L1 最强二级标注、轨迹回放与 hover 历史曲线。
- **策略模拟 / 策略回测（run 目录模型，对齐聚宽交互）**：一次运行一个 `data/sim/runs/{run_id}/`（meta.json + equity/trades/positions/state/run.log），回测与模拟同构。run_id 约定：`{strategy}__main`（每日主模拟）/ `{strategy}__bt_{ts}`（回测）/ `{strategy}__sim_{ts}`（额外模拟）。策略回测页：运行回测（区间/频率/资金）→ 回测列表（创建时间/区间/用时/频率/策略收益/基准收益/最大回撤/状态）→ 回测详情。策略模拟页：模拟列表（全部/进行中/已关闭；累计/年化/今日/最大回撤）→ 新建模拟（零起点 或 以某次已完成回测为起点）→ 模拟详情。两者详情同一套渲染：顶部指标条（累计/年化/总资产/可用资金/仓位占比/夏普/最大回撤）+ 左侧分节导航（收益概述/交易详情/每日持仓&收益/日志输出）+ 两行指标格 + 累计收益三线曲线（缩放/对数轴/单线开关）+ 每日盈亏柱；模拟详情额外有日期导航（默认最新/前后交易日/一键最新，`/api/run?asof=` 截断重算）与盘中实时点（最新 state 快照拼入净值序列，15s 轮询）。回测详情可一键「以此回测为起点模拟」。被 FILL_SIM 抽掉的订单在交易详情里单列为已拒单。

单测：`.venv/bin/python tests/test_ticai_data_source.py`（history_bars 与面板逐值对齐、instrument 数量、代码映射往返、bar_count=None 语义、is_suspended 不被时分秒误导）。

**校准日志与轨迹标注**：雷达每 cycle(20s) 记录涨幅≥3% 或概率≥0.2 的全量样本（含负例）→ `data/live/radar_log_YYYYMMDD.jsonl`（t/pct/s1/s3/s5/vr/tover/dist/prob/dp/heat/trank/dheat/theme/near）。收盘 `label_radar.py` 挂结果标签（是否涨停/连板/首封/末封/炸板次数），汇总每 stock-day 概率轨迹与 lead30/lead50（雷达提前首封分钟数）→ `radar_labeled_YYYYMMDD.jsonl`；`python apps/label_radar.py DATE CODE` 可追溯单只分钟级轨迹。日志粒度 2026-08 由 1 分钟加密到 20 秒——研究05 发现 1 分钟粒度会丢失拉升轨迹（涨停股首条≥4%日志平均已在 +9%）。

**限流保护**：腾讯并发 8 线程，扫描完整性 <90% 时周期间隔指数退避 20s→40s→80s（封顶×4）；东财板块榜每分钟仅拉一次，失败退避 5 分钟并复用缓存。QMT 源设防陈旧三道闸（推送时间戳校验 + 增量累积完整性 + 降级日 bar 横截面）。

## 策略模拟框架

基于 rqalpha 6.3.0，通过自写的 `rqalpha_mod_ticai` 接入项目数据源（不用米筐
bundle）。架构决策见 `docs/adr/`，策略开发规范见 `strategies/_template/SPEC.md`，
领域术语见 `CONTEXT.md`。

```bash
# 回放某一历史日（实盘验证，非历史回测 — 见 ADR-0004）
python apps/sim.py --replay --date 20260903

# 回放一段区间
python apps/sim.py --replay --start 20260827 --end 20260903

# 盘中实时（bash start.sh 会自动按 strategies.yaml 拉起）
python apps/sim.py

# 只跑指定策略 / 列出清单
python apps/sim.py --strategy v5_daban --replay --date 20260903
python apps/sim.py --list

# AI Feed 产出（补产历史日必须用 --at 指定当时时刻，否则时间戳闸门会滤掉）
python apps/ai_feed.py --date 20260903 --at 08:30:00
python apps/ai_feed.py --loop          # 盘中持续产出
```

落盘：

- `data/sim/runs/{run_id}/state/{date}.json` — 当日状态快照（看板实时数据源）
- `data/sim/runs/{run_id}/equity.parquet` — 跨日净值序列（Sharpe/IR 从这算）
- `data/sim/runs/{run_id}/run.log` — 运行日志
- `data/sim/ai_feeds/` — AI Feed（共享 + `private/{strategy}/` 私有）

关键约束（均由框架施加，策略不需自己实现）：涨停价不能买、一字板买不进、
bar 无量撤单、单笔 ≤ bar 成交量 25%、T+1 当日买入不可卖、FILL_SIM 成交概率
抽样（模拟涨停排队买不进，不加会系统性高估胜率）。

## 依赖

Python ≥ 3.10。pandas（**>=2.0,<3.0** — 上界由 rqalpha 决定，见 ADR-0002）/
numpy / tushare / pyarrow / akshare / requests；策略模拟额外需要 rqalpha（带入
rqrisk/h5py/logbook 等）与 scikit-learn（仅 research 部分脚本用）；
`QUOTE_SOURCE=qmt` 时额外需要 redis（见 requirements.txt）。

全部服务统一跑在项目 `.venv` 里（Homebrew 系统 Python 是 PEP 668
externally-managed，pip 装不进）。首次使用：

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

网络请求全部使用标准库 urllib，无额外 HTTP 框架依赖。大 QMT 快路径依赖外部
`xtquant_big_convert` 桥接服务（非本项目依赖，路径由 `BIGQMT_SRC_PATH` 指定）。
